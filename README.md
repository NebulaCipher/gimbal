# 云台上板

目标：STM32F407 C 板。当前已接入 yaw 控制和上下板通信；pitch 暂不输出，摩擦轮、拨弹电机不参与控制。

## 编译

在本目录执行：

```powershell
cmake --preset Debug
cmake --build --preset Debug
python tests/test_yaw_control.py
```

上板固件为 `build/Debug/Gimbal.elf`，下板固件仍为父目录的 `build/Debug/C_project.elf`。上下板均需更新，才能使用新增的 yaw 摇杆字段。测试使用主机 g++，模拟 HAL 和传感器输入，执行实际控制任务及 PID，覆盖启动等待、使能、超时、恢复、时间戳回绕和负角度编码。

## CAN1 协议与控制归属

上下板 CAN1 经滑环连成同一条总线；当前配置为 1 Mbit/s。

| ID | 发送者 → 接收者 | 数据 |
|---|---|---|
| `0x03` | 上板 → yaw 电机 | DM MIT 控制；只有上板发送 |
| `0x13` | yaw 电机 → 上下板 | DM 原生 8 字节反馈；位置 16 位、速度 12 位、力矩 12 位 |
| `0x510` | 下板 → 上板 | byte 2：使能 0/1；byte 3：pitch 摇杆；byte 4：yaw 摇杆；其他字节保留 |
| `0x114` | 上板 → 下板 | byte 0～2：有符号 24 位 IMU yaw × 10000，高字节在前；byte 3：电机角度诊断值；byte 4：yaw 标定等待结束且电机反馈新鲜，1 表示就绪；其余保留 |

`0x510` 的摇杆值把 `[-1, 1]` 线性映射为 `[0, 255]`。使能期间下板每 10 ms 发送一次，停用和等待期间也持续发送，且使能为 0。上板不再直接连接或解码 DT7。

下板直接用 `0x13` 电机位置计算云台与车身的相对方向，不再从 `0x114` 的 byte 3 取坐标变换角度。上板 IMU yaw 用于对地稳向，不能用相对电机位置替代。下板使用 byte 4 进行底盘运动联锁：就绪位为 0 时四轮发零电流，清除轮速目标并重置轮速/跟随 PID；就绪位为 1 时允许运动，遥控器使能及原有启动等待条件仍需满足。下板不检查状态报文或 yaw 电机反馈是否超时，就绪状态保持最近一次有效报文的值，初始值为未就绪。

联锁期间下板仍持续发送 `0x510`；其中的使能仅取决于遥控器及下板启动等待，不取决于云台就绪状态，避免两板互相等待。上板就绪位目前只表示 yaw 启动等待结束且电机反馈有效，不包含尚未接入的 pitch 轴。

## 控制行为

- 上板 IMU 初始化完成后启动看门狗和 1 kHz 任务；前 1000 次采样计算三轴陀螺仪偏置，前 2000 次任务只向 yaw 发零力矩。标定期间保持静止。
- 上板初始化时发送 yaw 使能帧以获取反馈；正常控制还要求下板使能、下板指令及 yaw 电机反馈均未超时（100 ms）。
- 失能或超时后发零力矩并重置 PID；恢复时从当前 IMU yaw 开始，不沿用旧目标角。
- 右摇杆水平死区 0.2，最大目标角速度 2 rad/s；回中保持目标角。角度环 `(5, 0, 0)`、速度环 `(1, 0, 0)` 沿用原下板初值，速度环使用去偏后的上板 IMU Z 轴角速度，力矩限幅 4 N·m。
- 只有完整且使能字段合法的 `0x510` 帧刷新看门狗；长时间收不到下板指令会复位。看门狗在 IMU 初始化之后启动。

## 实机待确认

驱动沿用本工程 DM4310 范围：位置 ±π rad、速度 ±21 rad/s、力矩 ±7.5 N·m。电机实际配置必须与之相符；`RX_ID = TX_ID + 0x10` 是本车确认的配置，并非软件自动推导的电机通用规则。

IMU 当前采用单位安装矩阵。实机需确认上板 IMU 安装朝向、Z 轴正方向与 yaw 正力矩方向匹配，再调整 PID。下板 `horizon_yaw` 仍需在云台和车身正前方对齐时读取电机位置进行标定，未标定不能保证平移方向正确。

pitch 接入前还需确认 DM-J4340 的反馈 ID、位置/速度/力矩量程、机械上下限和控制正方向；目前只接收并保留 pitch 摇杆量，不向其 CAN2 发送电机命令。

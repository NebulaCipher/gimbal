# 云台上板

目标：STM32F407 C 板。当前已接入 yaw、pitch 控制和上下板通信；pitch 已按实测行程和方向开启控制，PID 仍需实车整定，摩擦轮、拨弹电机不参与控制。

## 编译

在本目录执行：

```powershell
cmake --preset Debug
cmake --build --preset Debug
python tests/test_yaw_control.py
```

上板固件为 `build/Debug/Gimbal.elf`，下板固件仍为父目录的 `build/Debug/C_project.elf`。下板现有 `0x510` 已包含 pitch 摇杆，本次 pitch 接入无需修改下板。测试使用主机 g++，模拟 HAL 和传感器输入，执行实际控制任务、PID 和 DM4340 驱动，覆盖 yaw 原有行为及 pitch 反馈解码、控制帧编码、标定状态、角度保持、限位、安装反向和失能恢复。

## CAN1 协议与控制归属

上下板 CAN1 经滑环连成同一条总线；当前配置为 1 Mbit/s。

| ID | 发送者 → 接收者 | 数据 |
|---|---|---|
| `0x03` | 上板 → yaw 电机 | DM MIT 控制；只有上板发送 |
| `0x13` | yaw 电机 → 上下板 | DM 原生 8 字节反馈；位置 16 位、速度 12 位、力矩 12 位 |
| `0x510` | 下板 → 上板 | byte 2：使能 0/1；byte 3：pitch 摇杆；byte 4：yaw 摇杆；其他字节保留 |
| `0x114` | 上板 → 下板 | byte 0～2：有符号 24 位 IMU yaw × 10000，高字节在前；byte 3：电机角度诊断值；byte 4：yaw 标定等待结束且电机反馈新鲜，1 表示就绪；其余保留 |

`0x510` 的摇杆值把 `[-1, 1]` 线性映射为 `[0, 255]`。使能期间下板每 10 ms 发送一次，停用和等待期间也持续发送，且使能为 0。上板不再直接连接或解码 DT7。

下板直接用 `0x13` 电机位置计算云台与车身的相对方向，不再从 `0x114` 的 byte 3 取坐标变换角度。上板 IMU yaw 用于对地稳向，不能用相对电机位置替代。下板使用 byte 4 进行底盘运动联锁：就绪位为 0 时四轮发零电流，清除轮速目标并重置轮速/跟随 PID；就绪位为 1 时允许运动，遥控器使能及原有启动等待条件仍需满足。下板不检查状态报文或 yaw 电机反馈是否超时，就绪状态保持最近一次有效报文的值，初始值为未就绪。

联锁期间下板仍持续发送 `0x510`；其中的使能仅取决于遥控器及下板启动等待，不取决于云台就绪状态，避免两板互相等待。上板就绪位仍只表示 yaw 启动等待结束且电机反馈有效，不包含 pitch，允许在 pitch 标定期间调试 yaw 和底盘。

## CAN2 pitch 接入

上板 CAN2 为 1 Mbit/s；只控制 DM-J4340，不发送摩擦轮、拨弹电机命令。

| ID | 发送者 → 接收者 | 数据 |
|---|---|---|
| `0x09` | 上板 → pitch 电机 | MIT 使能或控制帧 |
| `0x19` | pitch 电机 → 上板 | 原生 8 字节反馈；由 `HW_can.cpp` 的 FIFO1 回调解析 |

复用原有 `dm4340_drv.cpp/.hpp`：位置 ±π rad，速度 ±10 rad/s，力矩 ±28 N·m；这些是协议映射量程，必须与电调配置一致，不是软件允许的行程或控制输出限幅。说明书第 6～7 页规定了反馈格式和 MIT 位布局，且明确位置、速度、力矩的量程可由调试助手配置；不能用说明书中的额定/峰值扭矩直接替换协议量程。

## 控制行为

- 上板 IMU 初始化完成后启动看门狗和 1 kHz 任务；前 1000 次采样计算三轴陀螺仪偏置，前 2000 次任务向 yaw/pitch 发零力矩。标定期间保持静止。
- 上板初始化时发送 yaw/pitch 使能帧以获取反馈；正常控制还要求下板使能、下板指令及 yaw 电机反馈均未超时（100 ms）。pitch 额外要求自身开关打开、行程有效且自身反馈未超时（100 ms）；pitch 状态不影响 yaw 就绪位。
- 失能或超时后发零力矩并重置 PID；恢复时从当前 IMU yaw 开始，不沿用旧目标角。
- 右摇杆水平死区 0.2，最大目标角速度 2 rad/s；回中保持 IMU yaw 目标角 `position`，跟随、分离和小陀螺均执行该闭环。小陀螺时相对电机角度会变化，对地朝向才是稳向目标。
- yaw 角度环为 `(8, 0, 0)`，输出 `yaw_target_omega`，限幅 7.5 rad/s；速度环为 `(4, 0.5, 0)`，取消原先 ±4 N·m 的额外输出限制，采用 DM4310 协议配置的 `T_MIN/T_MAX`（当前 ±7.5 N·m）。速度环积分状态限制在 ±1，积分力矩最多 ±0.5 N·m；失能或超时清除积分。yaw 摇杆速度保持 2 rad/s。参数仍需实车整定。
- IMU 水平固定在 yaw 支架上，yaw 速度反馈直接使用 `gimbal_omega = gyro_data[2]`，单位 rad/s；不进行支架倾斜换算。
- 右摇杆垂直控制 pitch，上推为正，通过 `pitch_motor_direction=-1` 减小电机位置目标、抬高枪管；死区 0.2，摇杆目标速度 0.8 rad/s（约 45.8°/s），回中保持相对机构的电机位置。位置环 `(8, 0, 0)`，输出限幅 1.2 rad/s；速度环暂用 `(12, 0, 0)`，积分状态限幅为 0，以排查积分对振荡的影响。取消原先 ±9 N·m 的额外输出限制，速度环输出及叠加前馈后的力矩只约束到 DM4340 的协议量程（当前 ±28 N·m）。重力前馈和行程保持原值。参数仍需实车整定。
- pitch 外环使用 `pitch_motor_t.para.pos`（rad），内环使用 `pitch_motor_t.para.vel`（rad/s）；两者在关中断期间一起快照，内环输出直接采用电机力矩方向，不额外乘反向系数。MIT 的 `kp=kd=0`，只下发外部串级 PID 算出的力矩，写法与 yaw 相同。反馈已有 CAN2 `0x19` 接收回调解析，无需新增协议。
- `pitch_target_omega` 为角度环输出，`pitch_pid_torque` 为叠加前馈之前的比例力矩；上抬速度为负，向下制动的比例修正为正。当前诊断参数关闭积分，重力前馈不准确或存在持续负载时，允许出现静态位置偏差；待确认振荡原因后再决定是否恢复积分。失能、反馈超时或限位禁止向外施力时重置 PID。前馈与比例输出叠加后，按 `DM4340_T_MIN/DM4340_T_MAX` 限制到可编码范围，避免 12 位力矩字段溢出回绕。协议量程必须与电调配置一致，不代表电机保证能够持续输出该力矩。
- 电机近似静止、两环未饱和时，yaw 的位置偏差比例修正约为 `8 * 4 * 位置偏差` N·m，pitch 约为 `8 * 12 * 位置偏差` N·m。本轮只将 pitch 速度环 Ki 从 2 暂降至 0，并将积分状态限幅从 0.5 置为 0；两环 Kp、重力前馈和摇杆目标速度保持原值。实际回正能力仍受电机及电调能力约束。位置目标的速度限幅及 pitch 机械行程限位继续生效。主机模型不能验证真实机构的延迟、间隙和共振，是否消除振荡需实车验证。
- 重力前馈为 `pitch_motor_direction * pitch_gravity_gain * cos(pitch_motor_position - pitch_gravity_angle)`。幅值暂按用户估计取 7 N·m；`pitch_gravity_angle` 表示最大重力矩处的电机位置，暂取 0 rad，尚未实测。先记录枪管水平时的电机位置作为初始基准，再根据实际重心校准。按电机输出轴与 pitch 关节 1:1、水平支架、重心相对机构固定计算。电机位置为基准、目标误差和速度均为 0 时，前馈约为 -7 N·m，失能时不发送前馈。
- 只有完整且使能字段合法的 `0x510` 帧刷新看门狗；长时间收不到下板指令会复位。看门狗在 IMU 初始化之后启动。

## 实机待确认

驱动沿用本工程 DM4310 范围：位置 ±π rad、速度 ±21 rad/s、力矩 ±7.5 N·m。电机实际配置必须与之相符；`RX_ID = TX_ID + 0x10` 是本车确认的配置，并非软件自动推导的电机通用规则。

IMU 当前采用单位安装矩阵。实机需确认上板 IMU 安装朝向、Z 轴正方向与 yaw 正力矩方向匹配，再调整 PID。下板 `horizon_yaw` 仍需在云台和车身正前方对齐时读取电机位置进行标定，未标定不能保证平移方向正确。

调试 yaw 稳向时，摇杆回中，观察上板 `position`、`euler_angles[0]`、`yaw_target_omega`、`gimbal_omega` 和 `torque`。连续使能期间 `position` 应保持固定，枪口被扰动后应回到该目标；跨越 ±π 时按最短角度差比较。若 `position` 随被带偏后的实际角度一起改变，先查使能/通信是否中断或上板是否复位。若目标固定而实际角度偏离，则需根据速度反馈和力矩整定 PID；力矩长期达到协议量程边界时也要检查负载和电机配置。IMU 仅有陀螺仪和加速度计，不能消除长期绝对 yaw 零漂。

## pitch 行程标定与启用

配置集中在 `Tasks/main_task.cpp` 开头；yaw 和 pitch 的 PID 初始化、电机使能均在 `MainInit()`，运行判断与摇杆目标更新在 `MainTask()`，闭环计算分别在 `Gimbal_Yaw_Control()` 和 `Gimbal_Pitch_Control()`：

```cpp
bool pitch_control_enabled = true;
float pitch_motor_min = -0.836080313f;
float pitch_motor_max = 0.0557515621f;
float pitch_motor_direction = -1.0f;
float pitch_gravity_gain = 7.0f;
float pitch_gravity_angle = 0.0f;
```

已录入本车先前实测且留余量的电机位置：抬升端 -0.836080313 rad，下落端 0.0557515621 rad。最新手动最高读数约 -1.04 rad，不据此扩大软件行程。抬高枪管时电机位置减小，因此 `pitch_motor_direction=-1`，当前已开启控制。IMU 在只随 yaw 转动的支架上，不能直接测量枪管 pitch。

`pitch_position` 现在是电机位置目标，与 `pitch_motor_t.para.pos`、行程限位使用同一坐标，单位 rad；上推时减小，回中保持。`pitch_omega` 现在直接等于电机反馈速度，上抬时应为负，原先 IMU 算出的正速度不再用于 pitch 控制。重力前馈标定时，在中间行程支撑机构，记录静止时的电机位置和稳定托举力矩，再确定幅值与角度基准。若总力矩长期达到负向限幅仍无法抬升，核对实际反馈力矩、电机状态、驱动量程和负载，再决定限幅。

以下步骤用于需要重新标定时：

1. 先设 `pitch_control_enabled=false`，烧录上板。此时电机会使能并接收零力矩帧以返回反馈，但不会主动托住枪管；支撑好机构。上下板仍需通信，已有看门狗由下板 `0x510` 刷新。
2. 在 Ozone 观察 `pitch_feedback_count` 是否增长、`pitch_motor_t.para.pos`（rad）、`pitch_motor_t.para.vel`（rad/s）及原始位置 `pitch_motor_t.para.p_int`。缓慢移动机构，确认速度符号与位置变化一致，记录两端电机位置并保留制动余量，小值填入 `pitch_motor_min`、大值填入 `pitch_motor_max`。
3. 手动抬高时电机位置减小，`pitch_motor_direction=-1`；若增加则设为 `1`。该符号仅用于摇杆和重力前馈，位置、速度闭环均直接使用电机坐标。机械行程不能跨反馈 ±π 跳变；若跨越，需要调整电机零位或增加位置展开。改变电机零位后，行程和重力基准均需重新标定。
4. 确认反馈方向、上下限后，再设 `pitch_control_enabled=true`，重新编译，从小幅输入开始调 PID。观察 `pitch_position`、`pitch_motor_t.para.pos`、`pitch_target_omega`、`pitch_omega`、`pitch_pid_torque` 和 `pitch_torque`。上下限相同或超出协议位置量程时仍保持零力矩。

控制每周期把目标位置限制在电机行程内；到达限位后屏蔽继续向外的力矩，允许向内退回。已越过软件边界时，目标被约束到边界，可能产生向内恢复力矩。软件限位不能代替机械挡块，必须留出减速距离。

当前按水平支架处理，pitch 使用电机相对角度保持，yaw 使用板载 IMU 稳向。
